## Authentication & Authorization

### JWT Strategy
```typescript
// Token payload
{ email, userId, role, firstName, lastName }

// Token extraction: Bearer token from Authorization header
// Expiration: 24 hours (configurable via JWT_EXPIRES_IN)
```

### Guards & Decorators
```typescript
// Protect route (require valid JWT)
@UseGuards(JwtAuthGuard)

// Require specific roles
@UseGuards(JwtAuthGuard, RolesGuard)
@Roles('admin')

// Access current user in handler
@Request() req  // req.user contains JWT payload
```

### User Approval Workflow
1. User registers → status: `pending`
2. Admin reviews → approves with generated password OR rejects
3. Approved user receives email with credentials
4. First login → can change password

### Roles
- **admin** - Full system access, user management, approvals
- **sitter** - View assigned bookings, manage availability, update visits
- **client** - Manage own pets, request bookings, view invoices

## Data Models

### User Schema (Core Fields)
- `email` (unique), `password`, `firstName`, `lastName`
- `role` (client | admin | sitter), `status` (active | pending | rejected)
- `phoneNumber`, `cellPhoneNumber`, `homePhoneNumber`
- `profilePicture` (Cloudinary URL)
- `address`, `zipCode`, `city`, `state`, `country`, `residenceType`
- `pendingAddress` (address change requests requiring admin approval)
- Emergency contact fields
- **Sitter-specific:** `areasCovered`, `petTypesServiced`, `hourlyRate`, `about`, `experience`
- **Client-specific:** `assignedSitterId`, `keyHandlingMethod`, home care info fields

### Pet Schema
- `userId` (owner reference), `name`, `type`, `breed`, `gender`, `dateOfBirth`
- `photo`, `photos[]` (Cloudinary URLs)
- Medical: `spayedNeutered`, `microchipNumber`, `vaccinations`, `medications`, `allergies`
- Related schemas: **PetCare** (feeding, behavior), **PetMedical** (vet info)

### Booking Schema
- `userId` (client), `sitterId`, `startDate`, `endDate`
- `serviceType`, `numberOfPets`, `petTypes[]`
- `status` (pending → confirmed → assigned → in_progress → completed → cancelled)
- `totalAmount`, `paidAmount`, `paymentStatus`, `paymentMethod`
- `visits[]` (date, notes, photos, duration, activities)
- `adminNotes`, `clientNotes`, `sitterNotes`

### Availability Schema
- `sitterId`, `weeklySchedule` (Mon-Sun with startTime/endTime)
- `maxDailyBookings`, `advanceNoticeHours`, `travelDistance`
- `unavailableDates[]`, `holidayRates`, `weekendRates`
- **AvailabilitySlot:** Individual time slots with booking references

## API Endpoint Patterns

### Standard CRUD Pattern
```typescript
@Controller('resource')
export class ResourceController {
  @Post()                    // Create
  @Get()                     // List all
  @Get(':id')                // Get one
  @Put(':id')                // Update
  @Delete(':id')             // Delete
}
```

### Common Decorators
```typescript
@Controller('route')
@UseGuards(JwtAuthGuard)           // Auth required
@UseGuards(JwtAuthGuard, RolesGuard)
@Roles('admin', 'sitter')         // Role restriction
@UseInterceptors(FileInterceptor('file'))  // File upload
@UsePipes(ValidationPipe)          // DTO validation
```

### Response Patterns
- Success: Return data directly or `{ message, data }`
- Errors: Throw NestJS exceptions (`NotFoundException`, `UnauthorizedException`, `BadRequestException`)
- Lists: Return array of documents
- Pagination: Not currently implemented (consider for large datasets)

## Coding Standards

### DO:
- Use dependency injection via constructor
- Validate all inputs with DTOs and class-validator decorators
- Use Mongoose `lean()` for read-only queries when performance matters
- Handle ObjectId validation before database queries
- Use async/await consistently
- Throw appropriate HTTP exceptions from NestJS
- Use environment variables for all secrets/config
- Add proper TypeScript types
- Follow NestJS naming conventions (*.module.ts, *.service.ts, *.controller.ts)

### DON'T:
- Don't expose sensitive data in responses (passwords, tokens)
- Don't hardcode URLs, secrets, or configuration values
- Don't skip DTO validation for user inputs
- Don't use raw MongoDB queries when Mongoose methods suffice
- Don't create circular module dependencies
- Don't bypass guards for sensitive operations

## Common Tasks

### Adding a New Module
1. Create folder structure: `src/<name>/`
2. Create schema in `schemas/<name>.schema.ts`
3. Create DTOs in `dto/create-<name>.dto.ts` and `dto/update-<name>.dto.ts`
4. Create service, controller, and module files
5. Import module in `app.module.ts`

### Adding a New Endpoint
1. Add method to controller with proper decorators
2. Add business logic to service
3. Create/update DTO if needed
4. Add guards if route requires auth/roles

### Database Operations
```typescript
// Create
this.model.create(dto);

// Find
this.model.find(filter).exec();
this.model.findById(id).exec();
this.model.findOne(filter).exec();

// Update
this.model.findByIdAndUpdate(id, update, { new: true }).exec();

// Delete
this.model.findByIdAndDelete(id).exec();

// Populate references
this.model.find().populate('userId', 'firstName lastName email').exec();
```

## Troubleshooting

- **MongoDB connection issues:** Check `MONGODB_URI` format and network access in Atlas
- **JWT errors:** Verify `JWT_SECRET` matches between token generation and validation
- **Email failures:** Ensure Gmail App Password is correct and 2FA is enabled
- **File upload errors:** Check Cloudinary credentials and file size limits
- **CORS issues:** Currently set to `origin: true` (all origins allowed)
- **Docker build failures:** Clear Docker cache with `docker system prune -f`
